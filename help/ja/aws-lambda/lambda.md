# AWS Lambda 上の Redmine

Redmine Kit AWS Lambda は、Redmine を AWS Lambda で動かすための調整をします。システム管理者向けのプラグインで、ユーザーから見た違いはありません。機能が有効になるのは、Lambda のように環境変数 `REDMINE_ROLE` (`web`、`worker`、`task`) を設定しているときだけです。設定していなければ、Redmine はいつもどおりに動きます。このプラグインには専用のページがなく、AWS の API も呼びません。

## 変更する内容

- Lambda Web Adapter の `/events` へのリクエストには空の応答 (204) を返し、CloudFront が転送するホスト名 (`X-Forwarded-Host`) をリクエストのホストにします。
- Redmine の実行中にアセットをコンパイルしません。
- Lambda では動かない Redmine の設定を無効に固定します (下記)。

## ステータスの表示

「管理」›「AWS」›「ステータス」(Redmine Kit AWS) に、次の項目を表示します。

- 「Lambda 関数」: ページを返した関数の「関数名」、「実行ロール」(`REDMINE_ROLE` の値)、「バージョン」、「メモリ」、「リージョン」、「イメージ URI」です。
- 「読み取り専用の設定」: Lambda で固定している Redmine の設定とその値です。

同じタブの「バージョン」に、このプラグインとそのバージョンを表示します。

## Lambda で固定する設定

Lambda では、必要な処理を実行できないため、次の設定はいつも無効です。

- 「コミットを自動取得する」と「リポジトリ管理用のWebサービスを有効にする」(「管理」›「設定」›「リポジトリ」)
- 「受信メール用のWebサービスを有効にする」(「管理」›「設定」›「受信メール」)

これらは無効のフィールドで、「この環境では設定できません」と表示します。以前に保存した値はデータベースに残りますが、使いません。「使用するバージョン管理システム」とリポジトリのフォームには、Subversion と Git、およびそれをもとにしたリポジトリの種類だけを表示します。
